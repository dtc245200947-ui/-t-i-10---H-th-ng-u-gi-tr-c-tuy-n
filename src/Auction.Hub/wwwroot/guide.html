Hướng dẫn đọc từng lệnh của Auction.Api (ASP.NET Core Minimal API), BidValidation.Grpc (gRPC Service), RabbitMQ Event Bus, Auction.Hub (SignalR) và Audit.Worker — biên soạn theo đúng chuẩn tài liệu giảng dạy mẫu.

01 So sánh từ bài mẫu Catalog.Api lên Đề tài 10 (Hệ thống Đấu giá)

Trong tài liệu mẫu Catalog.Api, dữ liệu chỉ được lưu tạm trong một biến List<ProductDto> trên RAM và sinh mã bằng products.Max(p => p.Id) + 1. Ở Đề tài 10, chúng ta nâng cấp toàn bộ các điểm hạn chế đó để đạt chuẩn Hệ thống Phân tán thực tế:

  • Lưu trữ bền vững bằng Database (Entity Framework Core): Thay List<ProductDto> bằng AuctionDbContext (hỗ trợ PostgreSQL trên Docker và SQLite WAL trên máy cá nhân). Tắt máy bật lại dữ liệu vẫn còn nguyên.
  • Định danh toàn cục bằng Guid: Thay int Id (Max + 1) bằng Guid.NewGuid() và route constraint {id:guid}, triệt tiêu hoàn toàn lỗi trùng ID khi nhiều người gửi POST cùng thời điểm.
  • Tách dịch vụ kiểm tra giá qua gRPC: Thay vì chỉ viết một câu lệnh if đơn giản trong API, Auction.Api gọi sang dịch vụ độc lập BidValidation.Grpc qua HTTP/2.
  • Đồng bộ sự kiện bất đồng bộ qua RabbitMQ & SignalR: Khi có giá mới hợp lệ, sự kiện BidAccepted được phát qua RabbitMQ tới Auction.Hub (đẩy realtime xuống trình duyệt) và Audit.Worker (ghi lịch sử chống trùng lặp).

02 Mã nguồn cốt lõi của Auction.Api được đánh số theo từng nhóm

Dưới đây là cấu trúc rút gọn có đánh số dòng của src/Auction.Api/Program.cs để bạn dễ dàng đối chiếu khi đọc giải thích bên dưới:

Nhóm A. Khởi tạo, đăng ký DI (Database, RabbitMQ, gRPC) và Middleware

01  var builder = WebApplication.CreateBuilder(args);
02  var httpPort = builder.Configuration.GetValue<int>("Server:Port", 5050);
03  builder.WebHost.UseUrls($"http://0.0.0.0:{httpPort}");
04
05  builder.Services.AddAuctionDatabase(builder.Configuration);
06  builder.Services.Configure<RabbitMqSettings>(builder.Configuration.GetSection("RabbitMQ"));
07  builder.Services.AddSingleton<RabbitMqEventPublisher>();
08  builder.Services.AddHostedService<AuctionExpirationService>();
09
10  var grpcAddress = builder.Configuration["GrpcServices:BidValidationUrl"] ?? "http://localhost:5051";
11  builder.Services.AddGrpcClient<BidValidator.BidValidatorClient>(o => o.Address = new Uri(grpcAddress));
12
13  var app = builder.Build();
14  await app.Services.EnsureAuctionDatabaseSeededAsync();

Nhóm B. Các API GET tra cứu phiên đấu giá

15  app.MapGet("/auctions", async (string? status, AuctionDbContext db) => {
16      var query = db.Auctions.AsNoTracking().AsQueryable();
17      if (!string.IsNullOrWhiteSpace(status))
18          query = query.Where(a => a.Status.ToLower() == status.ToLower());
19      var items = await query.OrderByDescending(a => a.Status == "Open").ThenBy(a => a.EndTimeUtc).ToListAsync();
20      return Results.Ok(items.Select(a => ToAuctionDto(a, DateTime.UtcNow)));
21  });
22
23  app.MapGet("/auctions/{id:guid}", async (Guid id, AuctionDbContext db) => {
24      var auction = await db.Auctions.AsNoTracking().FirstOrDefaultAsync(a => a.Id == id);
25      return auction is null
26          ? Results.NotFound(new { message = $"Không tìm thấy phiên đấu giá với ID '{id}'." })
27          : Results.Ok(ToAuctionDto(auction, DateTime.UtcNow));
28  });

Nhóm C. API POST tạo phiên đấu giá mới

29  app.MapPost("/auctions", async (CreateAuctionRequest request, AuctionDbContext db) => {
30      if (string.IsNullOrWhiteSpace(request.ProductName) || request.StartingPrice <= 0)
31          return Results.BadRequest(new { message = "Tên sản phẩm không được trống và giá khởi điểm > 0." });
32
33      var auction = new AuctionItem {
34          Id = Guid.NewGuid(),
35          ProductName = request.ProductName.Trim(),
36          StartingPrice = request.StartingPrice,
37          CurrentPrice = request.StartingPrice,
38          Status = "Open"
39      };
40      db.Auctions.Add(auction);
41      await db.SaveChangesAsync();
42      return Results.Created($"/auctions/{auction.Id}", ToAuctionDto(auction, DateTime.UtcNow));
43  });

Nhóm D. API POST gửi mức giá mới (Kết nối gRPC + RabbitMQ)

44  app.MapPost("/auctions/{id:guid}/bids", async (
45      Guid id, PlaceBidRequest request, AuctionDbContext db,
46      BidValidator.BidValidatorClient grpcValidator, RabbitMqEventPublisher eventPublisher) =>
47  {
48      var auction = await db.Auctions.FirstOrDefaultAsync(a => a.Id == id);
49      if (auction is null) return Results.NotFound(new { message = "Không tìm thấy phiên đấu giá." });
50
51      var validationResult = await grpcValidator.ValidateBidAsync(new ValidateBidRequest {
52          AuctionId = auction.Id.ToString(),
53          AuctionStatus = auction.Status,
54          CurrentPrice = (double)auction.CurrentPrice,
55          MinIncrement = (double)auction.MinIncrement,
56          BidderName = request.BidderName ?? "",
57          BidAmount = (double)request.Amount
58      });
59
60      if (!validationResult.IsValid)
61          return Results.BadRequest(new PlaceBidResponseDto(false, validationResult.Message, ...));
62
63      auction.CurrentPrice = request.Amount;
64      auction.CurrentWinner = request.BidderName.Trim();
65      auction.TotalBids += 1;
66      db.Bids.Add(new BidRecord { AuctionId = auction.Id, BidderName = auction.CurrentWinner, Amount = request.Amount });
67      await db.SaveChangesAsync();
68
69      await eventPublisher.PublishEventAsync(envelope, "auction.bid.accepted");
70      return Results.Ok(new PlaceBidResponseDto(true, "Đặt giá thành công!", ...));
71  });

03 Giải thích từng lệnh: Khởi tạo, DI và Middleware (Dòng 01–14)

  • Dòng 01–03 (Khởi tạo và tách cấu hình Port): builder.Configuration.GetValue<int>("Server:Port", 5050) đọc cổng từ file appsettings.json hoặc biến môi trường Server__Port trong Docker Compose. Nếu không có mới lấy mặc định 5050.
  • Dòng 05 (Đăng ký Database): AddAuctionDatabase tự động kiểm tra biến cấu hình Database:Provider. Khi chạy trong Docker Compose sẽ kết nối tới container postgres; khi chạy trực tiếp trên máy tính sẽ dùng file SQLite dùng chung tại data/auction_system.db.
  • Dòng 07–08 (RabbitMQ & Background Worker):
    • AddSingleton<RabbitMqEventPublisher>(): Duy trì kết nối tới RabbitMQ Exchange auction.events để phát sự kiện.
    • AddHostedService<AuctionExpirationService>(): Dịch vụ chạy ngầm định kỳ kiểm tra các phiên đấu giá có EndTimeUtc <= DateTime.UtcNow để tự động chuyển trạng thái sang Closed và phát sự kiện AuctionEnded.
  • Dòng 10–11 (Đăng ký gRPC Client): AddGrpcClient<BidValidator.BidValidatorClient> tạo client gRPC kết nối tới BidValidation.Grpc ở cổng 5051. Lớp BidValidatorClient được trình biên dịch tự động sinh ra từ tệp Protos/bid_validation.proto.

04 Giải thích các API GET và Route Constraint {id:guid} (Dòng 15–28)

  • Tham số DI trong Lambda: Trong async (Guid id, AuctionDbContext db) =>, ASP.NET Core Minimal API tự động phân biệt: id lấy từ đường dẫn URL {id:guid}, còn db được tiêm (inject) từ Dependency Injection container.
  • Từ khóa async / await và FirstOrDefaultAsync: Khác với products.FirstOrDefault(...) chạy đồng bộ trên RAM trong bài mẫu, truy vấn cơ sở dữ liệu qua mạng/ổ cứng cần dùng bất đồng bộ await db.Auctions.FirstOrDefaultAsync(a => a.Id == id) để không làm nghẽn luồng (thread) của web server.
  • Toán tử điều kiện 3 ngôi (Ternary ? :): 
    return auction is null
    ? Results.NotFound(new { message = $"Không tìm thấy phiên đấu giá với ID '{id}'." })
    : Results.Ok(ToAuctionDto(auction, DateTime.UtcNow));
    Nếu không tìm thấy bản ghi trong bảng Auctions, trả về HTTP 404 Not Found; ngược lại chuyển đổi sang AuctionDto và trả về HTTP 200 OK.

05 Giải thích chi tiết Luồng Đặt Giá Phân Tán (Dòng 44–71)

Câu hỏi cốt lõi khi bảo vệ: "Khi người dùng bấm nút Đặt giá trên trình duyệt, những gì diễn ra ở phía sau?" — Bạn chỉ cần đọc đúng 4 bước từ Dòng 48 đến Dòng 70 dưới đây!
  1. Bước 1 — Tra cứu phiên đấu giá từ Database (Dòng 48–49): Gọi db.Auctions.FirstOrDefaultAsync(a => a.Id == id). Nếu không tồn tại thì trả về 404 Not Found.
  2. Bước 2 — Gọi dịch vụ kiểm tra giá độc lập qua gRPC (Dòng 51–58): Auction.Api đóng gói thông tin phiên (trạng thái, thời gian đóng/mở, giá hiện tại, bước giá tối thiểu) cùng mức giá người dùng gửi vào đối tượng ValidateBidRequest và gọi await grpcValidator.ValidateBidAsync(...) sang dịch vụ BidValidation.Grpc (cổng 5051).
    • Tại BidValidation.Grpc: Nếu phiên đã đóng (AUCTION_CLOSED), hết giờ (AUCTION_EXPIRED) hoặc mức giá đặt nhỏ hơn CurrentPrice + MinIncrement (BID_TOO_LOW), gRPC trả về IsValid = false.
    • Tại Dòng 60–61: Nếu !validationResult.IsValid, Auction.Api lập tức trả về 400 Bad Request kèm mã lỗi cho Client.
  3. Bước 3 — Cập nhật Database (Dòng 63–67): Khi gRPC xác nhận hợp lệ (IsValid == true), Auction.Api cập nhật auction.CurrentPrice = request.Amount, auction.CurrentWinner = request.BidderName.Trim(), tăng TotalBids += 1, thêm bản ghi mới vào db.Bids và gọi await db.SaveChangesAsync().
  4. Bước 4 — Phát sự kiện BidAccepted lên RabbitMQ (Dòng 69): Lệnh await eventPublisher.PublishEventAsync(envelope, "auction.bid.accepted") đẩy sự kiện lên Fanout Exchange auction.events.
    • Nhánh 1 (Realtime): Auction.Hub nhận sự kiện từ hàng đợi auction.hub.queue và phát qua SignalR (Clients.All.SendAsync("BidAccepted", ...)) giúp mọi màn hình nhảy giá mới ngay lập tức.
    • Nhánh 2 (Lịch sử & Kiểm toán): Audit.Worker nhận sự kiện từ hàng đợi auction.audit.queue, kiểm tra chống trùng lặp theo EventId (Idempotent) và lưu vào bảng AuditLogs.

06 Bảng tổng hợp cú pháp C# & Kiến trúc Phân tán cần thuộc khi thi

Cú pháp / Thành phần Ý nghĩa ngắn gọn để trả lời giảng viên
async / await Lập trình bất đồng bộ, giúp luồng xử lý không bị khóa cứng khi chờ Database, gRPC hoặc RabbitMQ.
?. và ?? ?. truy cập an toàn khi khác null; ?? lấy giá trị mặc định bên phải nếu vế trái là null.
{id:guid} Route constraint bắt buộc tham số trên URL phải có định dạng UUID/GUID hợp lệ.
AsNoTracking() Tăng tốc truy vấn đọc (GET) trong Entity Framework Core vì không cần theo dõi thay đổi đối tượng.
Fanout Exchange Loại Exchange trong RabbitMQ nhân bản sự kiện tới tất cả các Queue đang gắn (bind) vào nó (gồm Hub Queue và Audit Queue).
Idempotent Consumer Đảm bảo dù RabbitMQ có gửi lặp lại cùng 1 bản tin nhiều lần thì Audit.Worker chỉ ghi vào Database đúng 1 lần duy nhất dựa vào EventId.
Dead-Letter Queue (DLQ) Hàng đợi chứa các bản tin bị lỗi sau khi Audit.Worker đã thử lại (Retry) đủ 3 lần mà vẫn thất bại, giúp không làm kẹt hàng đợi chính.
